# Stitch Mail

Open-core **service plugin** for [Stitch Manager](https://github.com/StitchWB/Stitch-Manager):
the mail inbox / IMAP layer used by auto-registration — generates emails from settings, connects
IMAP/mail.tm providers, waits for verification emails, and manages inbox profiles + sync state.

- **Kind:** `service` (plugin id `stitch-mail`, service `mail`)
- **Runtime:** spawned by the Stitch `ServicePluginHost` as `python -m stitch_mail`, speaks
  JSON-RPC 2.0 (vendored `RpcPluginServer`)
- **Self-contained:** no `stitch_backend` imports; owns its own SQLite store for profile cache,
  sync states, and email counters.

## Commands

`generate_from_settings`, `generate_from_settings_persistent`, `test_strategies`, `connect`,
`disconnect`, `list`, `list_folders`, `get_by_id`, `wait_for_email`, `mark_as_read`, `delete`,
`create_mailtm_account`, `get_capabilities`, `get_provider_catalog`, `list_profiles`,
`wait_otp`, `sync`, `get_profile`, `upsert_profile`, `delete_profile`, `connect_profile`,
`get_sync_state`, `upsert_sync_state`.

## IMAP + Mail.tm

Session commands (`connect`, `list`, `wait_for_email`, `mark_as_read`, `delete`,
`list_folders`) run a real `imaplib` transport against the credentials in the connect input or
the stored profile; `mail_tm` sessions talk to the Mail.tm REST API (`httpx`). Mail.tm account
creation goes domains → account → login and returns `{address, password, baseUrl}`.

`wait_otp` (the `EmailVerificationProvider`/`MailInboxSPI` surface used by auto-registration)
resolves the mailbox from the plugin's profile store — exact credentials-username match first,
else the newest visible IMAP profile — and polls it with the raw-IMAP engine ported from the
core built-in provider. When no IMAP profile is visible the handler raises, so the host SPI
bridge falls back to the built-in `EmailService`.

**Timeout semantics:** the host kills every plugin call at 30s, so `wait_otp` caps its poll at
**25s** and returns `""` on genuine timeout; `wait_for_email` caps its wait the same way and
raises a timeout error. Waits longer than 30s are a known host contract gap (F02c/HA6) — the
caller's requested timeout above the cap is not honored.

## Layout

```
plugin.json              manifest (schema v2, declarative UI + i18n + commands + SPI)
stitch_mail/
  __main__.py            JSON-RPC entry point (RpcPluginServer)
  imap.py                raw imaplib operations + wait_otp poll engine
  mailtm.py              Mail.tm REST client (httpx)
  sessions.py            in-memory mailbox session store + command dispatch
  emailgen.py            email address derivation (strategies)
  storage.py             SQLite profile cache / sync states / counters
  _vendor/rpc_server.py  vendored RpcPluginServer (regenerated by stitch_plugin_tools; do not edit)
```

## Development

```bash
pip install ruff pytest
ruff check .
python -m pytest tests -q
```

The protocol tests drive `python -m stitch_mail` over raw stdin/stdout against an in-process
fake IMAP socket server and a fake Mail.tm HTTP server — no real network, no host dependency.
Integration tests for the host-side wiring (SPI bridge, dual routes) live in the private Stitch
monorepo; this repo's CI runs lint + the protocol suite, the monorepo runs the full
plugin-vs-core integration suite against the mirrored copy.

## Distribution

This plugin is **signed and distributed via the Stitch gated server** — the signing key lives in
the private hub, never in this repo. Released packages are assembled from this source, signed in
the hub, and published to the distribution server for entitled users.

## Contributing

External contributions are welcome — open a PR against this repo. Keep changes within the plugin
(no new `stitch_backend` imports, keep the package self-contained). The vendored
`_vendor/rpc_server.py` is regenerated from the core SDK — do not edit it by hand.
